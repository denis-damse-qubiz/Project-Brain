# Specifications

Specifications describe current agreed behavior by area. Create files named for their area and keep the index below current. Cite shared sources with paths relative to the `project-brain/` root, for example `internal-knowledgebase/transcripts/YYYY-MM-DD-source-topic.md`. Do not cite private knowledge.

## Format

```md
# <Area>

## Context

## Glossary

## Use Cases

## Domain Rules

- R-<AREA>-001 [planned] — <rule>. Source: `<shared-path>`

## Open Questions
```

Rule IDs use `R-<AREA>-001` and remain stable once assigned. Set every rule to `[planned]`, `[partial]`, or `[built]`; use `[from code - unconfirmed]` only for existing behavior awaiting confirmation. Make unknowns explicit and never invent a project fact.
