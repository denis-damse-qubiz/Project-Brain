# Internal knowledgebase

Use this area for team-visible raw input and dated decisions. Keep raw material separate from stakeholder-reviewable project knowledge.

Add one input per file under `transcripts/`, named `YYYY-MM-DD-<source>-<topic>.md`. Preserve history: record later corrections as new entries rather than changing prior input.

Turn a raw input or dated decision into a sourced rule in `../project-knowledgebase/specs/`, then add a scenario when applicable. Keep unanswered questions explicit and never fabricate a project fact.
